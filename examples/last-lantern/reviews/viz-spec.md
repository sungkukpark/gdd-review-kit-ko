# 시각화 명세 — 「마지막 등불」 GDD 리뷰 보드 인터랙티브 리포트

작성: viz-designer · 입력: `reviews/`의 여섯 리뷰어 파일, `reviews/SYNTHESIS.md`
대상 산출물: 프로젝트 루트 `review-viz.html` (html-builder가 작성)

이 명세는 `viz-data.json`을 보지 않고 작성했다. 아래에 쓰는 데이터 이름은 **의미**를 설명한 것이며 JSON 필드명이 아니다. 실제 필드와의 대응은 html-builder가 두 산출물을 받은 뒤 확인한다. 설계자가 원본 파일에서 직접 센 수치는 "검증용 참고치"로 표시했다. JSON과 다르면 JSON을 정본으로 쓰되, 차이를 빌드 보고에 적는다.

## 0. 설계 결정 요약

리뷰 데이터의 실제 모양은 다음과 같다. 이것이 선택과 탈락을 결정했다.

- 1라운드 지적 30개(리뷰어당 5개). 2라운드에서 심각도가 바뀐 지적은 **4개뿐**이다(상향 2, 하향 2). 철회된 지적은 없다.
- 2라운드 교차 검토 항목(충돌 C, 연결 L)은 모두 다른 리뷰어의 지적 ID를 명시적으로 참조한다. 리뷰어 간 참조 관계가 풍부하고 추적 가능하다.
- SYNTHESIS는 상위 5개 이슈(각각 원본 지적 ID 목록과 교차 검토 결과)와 **미해결 쟁점 6개**(각각 리뷰어별 입장)를 제공한다.

| 후보 | 결정 | 이유 |
|---|---|---|
| 심각도 분포 | **채택 (V4)** | 실제 개수를 세는 차트. 리뷰어별 편차(심리 전문가는 전부 MAJOR, BLOCKING은 세 명만)가 뚜렷하다. |
| 리뷰어 합의 매트릭스 | **채택 (V2)** | 이슈 × 리뷰어 격자. "여러 명이 독립적으로 같은 결함을 찾음"(합의)과 "미해결 쟁점 6개"(충돌)를 한 화면에서 대비시킨다. |
| 지적 사항 흐름(생키) | **탈락 → V4에 흡수** | 30개 중 26개가 같은 등급에 머문다. 생키로 그리면 굵은 직선 띠 세 개와 가는 선 네 개뿐인 장식이 된다. 대신 V4에 "1라운드 / 2라운드 최종" 전환과 "등급 변경 4건" 목록을 둔다. |
| 교차 검토 네트워크(노드-링크) | **형태 변경 → 매트릭스 (V3)** | 6개 노드, 방향 있는 간선 약 60개, 충돌/연결 두 종류. 노드-링크 그림은 선이 겹쳐 프로젝터에서 읽히지 않는다. 6×6 방향 매트릭스가 같은 통찰을 숫자로 정확히 보여 준다. |
| 상위 이슈 드릴다운 | **채택 (V1)** | 페이지의 핵심. 원본 지적 → 2라운드 논쟁 → 최종 상태 흐름을 이슈별로 보여 준다. |
| 필터링과 정렬 | **채택 (V5)** | 30개 전체 지적의 드릴다운 영역. 다른 시각화에서 클릭하면 이 표로 연결된다. |

최종 시각화: **5개.** (마스트헤드 요약 수치는 시각화가 아니라 헤더 텍스트로 취급한다.)

## 1. 전역 규칙

### 1.1 표시 라벨(반드시 이 문자열 그대로)

| 내부 값 | 표시 |
|---|---|
| `BLOCKING` | BLOCKING · 치명 |
| `MAJOR` | MAJOR · 주요 |
| `MINOR` | MINOR · 경미 |
| `SURVIVED` | SURVIVED · 유지 |
| `STRENGTHENED` | STRENGTHENED · 강화 |
| `WEAKENED` | WEAKENED · 약화 |

- 필터 버튼, 범례, 툴팁, 태그, 표 셀 모두 위 표시를 쓴다. 영문만 또는 한글만 쓰지 않는다.
- 심각도 **변경**은 교차 검토 결과와 다른 개념이다. "SURVIVED · 유지"와 혼동되지 않도록 심각도 변경에는 "등급 상향", "등급 하향", "등급 동일"이라는 별도 문구를 쓴다.
- 교차 검토 결과 태그는 **데이터에 명시된 값이 있을 때만** 표시한다. 설계자나 빌더가 추론해서 붙이지 않는다. 값이 없는 지적에는 태그를 생략한다(빈 태그나 "미정" 태그를 만들지 않는다).

### 1.2 리뷰어 표시 이름

| 식별자 | 전체 이름 | 좁은 칸용 짧은 이름 |
|---|---|---|
| systems-designer | 시스템 디자이너 | 시스템 |
| narrative-critic | 내러티브 비평가 | 내러티브 |
| player-psychologist | 플레이어 심리 전문가 | 심리 |
| feasibility-lead | 기술 실현성 리드 | 실현성 |
| adversarial-qa | 적대적 QA | QA |
| business-analyst | 제작/비즈니스 분석가 | 비즈니스 |

- 순서는 항상 위 표 순서로 고정한다(모든 축, 필터, 범례 공통).
- 짧은 이름은 V2·V3 매트릭스의 열 머리글에만 쓴다. 호버/포커스 툴팁에는 전체 이름과 영문 식별자를 함께 보여 준다.
- 지적 ID는 항상 `식별자/F번호` 형식(예: `systems-designer/F1`)으로 표시한다. 줄이지 않는다.

### 1.3 시각 스타일(4라운드 `review-board.html`과 통일)

- 배경 #16181D, 패널 #1F232B, 주 텍스트 #E8E6E1, 보조 텍스트 #8A8F98, 구분선 #2A2F38.
- **색은 심각도에만 쓴다.** BLOCKING #E5484D, MAJOR #F5A623, MINOR #5A6270. 충돌/연결, 입장 구분 등 심각도가 아닌 구분은 색이 아니라 텍스트 라벨, 굵기, 불투명도(주 텍스트 색의 명도 단계)로 표현한다.
- 심각도 태그: 심각도 색 1px 실선 테두리 + 투명 채움 + 심각도 색 글자. 영문 토큰은 대문자·넓은 자간, 한글 병기는 기본 자간. `white-space: nowrap`으로 태그 안에서 줄바꿈하지 않는다.
- 교차 검토 결과 태그: 주 텍스트 색 1px 테두리, 투명 채움(색 없음).
- 리뷰어 칩: 보조 텍스트 색 1px 외곽선, 색 없음.
- border-radius 4px 이하, 그림자·그라디언트·아이콘·이모지 금지.
- 한국어 텍스트에 `word-break: keep-all`. `<html lang="ko">`, `<meta charset="utf-8">`.
- 프로젝터 가독성: 본문과 지적 텍스트 최소 18px, 매트릭스 셀 숫자 최소 20px, 셀 라벨 최소 16px, 툴팁 최소 16px.
- 모션: 섹션 첫 표시 시 페이드업 1회가 최대. 펼침/접힘·차트 전환은 즉시 전환. `prefers-reduced-motion: reduce`이면 페이드업도 끈다.
- 외부 라이브러리·폰트·CDN 금지. 차트는 인라인 SVG 또는 CSS 그리드로 직접 그린다. 바닐라 JS만 쓴다.

### 1.4 공통 인터랙션

- **툴팁**: 마우스 호버와 키보드 포커스 모두에서 표시한다. 터치/클릭으로 연 툴팁은 바깥을 누르거나 Esc로 닫힌다. 툴팁은 뷰포트 밖으로 나가지 않게 위치를 뒤집는다.
- **지적 ID 링크**: 페이지 어디에서든 지적 ID(예: `adversarial-qa/F2`)는 클릭 가능한 텍스트다. 클릭하면 V5 표의 해당 행으로 스크롤하고, 그 행을 펼치고, 활성 필터 때문에 행이 숨겨져 있으면 필터를 "전체"로 초기화한 뒤 이동한다. 도착한 행은 좌측 2px 주 텍스트 색 막대로 2초간 표시한다(애니메이션 없이 켰다가 끈다).
- 모든 클릭 가능한 요소는 `<button>` 또는 `<a>`로 만들고 `:focus-visible` 외곽선(주 텍스트 색 2px)을 둔다. 펼침 요소에는 `aria-expanded`를 쓴다.

| 2 | **V2 합의와 쟁점 매트릭스** | 약 700px |

페이지 상단에 고정 목차 막대는 두지 않는다. 대신 헤더 아래 한 줄 앵커 목록: "상위 5개 이슈 · 합의와 쟁점 · 교차 검토 · 심각도 분포 · 전체 지적".

### 2.1 헤더 요약 수치

큰 숫자(64px 디스플레이 서체) + 라벨(18px 보조 텍스트) 3개, 가로 배치.

| 수치 | 라벨 | 검증용 참고치 |
|---|---|---|
| 전체 1라운드 지적 수 | 전체 지적 | 30 |
| 2라운드 최종 BLOCKING 수 | BLOCKING · 치명 (최종) | 3 (1라운드 2) |
| SYNTHESIS 미해결 쟁점 수 | 미해결 쟁점 | 6 |

BLOCKING 숫자 아래에 보조 텍스트로 "1라운드 2 → 2라운드 3"을 표시한다. BLOCKING 숫자 글자색만 #E5484D.
판정 한 줄은 SYNTHESIS 4장의 "한 줄 판정" 문장을 그대로 쓴다: "문서가 약속한 게임을 검증할 기준이 없으니, 수용 기준과 리뷰 게이트부터 세워야 한다."

## 3. V1 — 상위 5개 이슈 드릴다운

### 목적
SYNTHESIS의 상위 5개 이슈를 순위대로 보여 주고, 펼치면 "누가 처음 지적했는가 → 2라운드에서 어떻게 다퉜는가 → 최종 상태"를 한 흐름으로 읽게 한다. 멀티 에이전트 방식의 성과(여러 명이 독립적으로 같은 결함을 찾고, 서로 반박해 등급을 조정함)가 가장 직접적으로 보이는 곳이다.

### 형태
전체 폭 펼침 카드 5장, 세로로 1~5위 순서. 카드 사이 #2A2F38 헤어라인, 박스 테두리 없음.

### 필요한 데이터(의미)
각 이슈마다:
- 순위(1~5)
- 한 줄 문제 진술(SYNTHESIS 소제목 그대로)
- 최종 심각도, 그리고 심각도에 붙은 단서 문구(예: 1위의 "feasibility-lead/F1을 2라운드에서 상향한 등급")
- 교차 검토 결과 값과 단서 문구(예: 3위의 "심각도와 문제 진술이 반박되었다. 진단 자체는 반박되지 않았다.")
- 원본 지적 ID 목록(리뷰어 식별자 + F번호)과 각 원본의 1라운드 심각도·제목
- 2라운드 논쟁 항목 목록: 각 항목의 작성 리뷰어, 항목 ID(C1, L2, "수정" 등), 입장 구분(지지·강화 / 반박·하향 요구 / 보완·조건), 한두 문장 요지
- 관련 미해결 쟁점 번호(있을 때)
- SYNTHESIS 요지 문단

### 접힌 상태(기본)
```
[ 1 ]  BLOCKING · 치명   STRENGTHENED · 강화
 (90px, 보조색 25% 불투명)
       3층의 계단·"왕좌 방"·마왕 배치가 정의되지 않았고, 맵 생성이 실패했을 때의 처리도 없다   (28px)
       지적한 리뷰어 6명  [적대적 QA] [기술 실현성 리드] [시스템 디자이너] [내러티브 비평가] [플레이어 심리 전문가]
       원본 지적: adversarial-qa/F2 · adversarial-qa/F4 · feasibility-lead/F1 · ...     [펼치기 ▾ 대신 텍스트 "자세히 보기"]
```
- 순위 숫자: 약 90px, 디스플레이 서체, 보조 텍스트 색 25% 불투명도, 카드 왼쪽 120px 열.
- 문제 진술: 28px, 최대 2줄 뒤 줄바꿈 허용(말줄임 금지).
- "지적한 리뷰어 N명": N은 원본 지적 ID의 **고유 리뷰어 수**. 합의 강도를 숫자로 보여 준다.
- 펼침 버튼 텍스트: 접힘 "자세히 보기", 펼침 "접기". 아이콘 화살표 금지.
- 여러 카드를 동시에 펼칠 수 있다.

### 펼친 상태
세 단계를 세로로 쌓는다. 각 단계 앞에 16px 보조 텍스트 소제목, 단계 사이 헤어라인.

1. **원본 지적 (1라운드)** — 원본 지적 ID마다 한 행: 심각도 태그(1라운드 등급) · 지적 ID(링크) · 지적 제목(18px). 2라운드에서 등급이 바뀐 원본은 행 끝에 "→ 2라운드 BLOCKING · 치명"처럼 최종 등급 태그를 덧붙인다.
2. **교차 검토 논쟁 (2라운드)** — 입장별 세 묶음, 순서 고정: "지지·강화" → "반박·하향 요구" → "보완·조건". 묶음이 비면 그 묶음을 숨긴다. 각 항목: 리뷰어 칩 · 항목 ID(예: `adversarial-qa · 2라운드 C1`) · 요지 1~2문장(18px). 요지는 리뷰 파일 문장을 줄인 것이어야 하며 새로 쓰지 않는다.
3. **최종 상태 (3라운드 종합)** — 최종 심각도 태그 + 교차 검토 결과 태그 + 각 단서 문구(보조 텍스트 16px). 관련 쟁점이 있으면 "미해결 쟁점 1로 이어짐" 텍스트 링크 → V2의 해당 쟁점 행으로 스크롤하고 그 행을 강조.

### 검증용 참고치(설계자가 SYNTHESIS와 리뷰 파일에서 확인한 내용)

## 4. V2 — 합의와 쟁점 매트릭스

### 목적
"보드가 어디서 합의했고 어디서 갈렸는가"를 한 격자에서 보여 준다. 위쪽 블록(상위 이슈)은 여러 칸이 채워진 행 = 합의, 아래쪽 블록(미해결 쟁점)은 한 행 안에 서로 다른 입장 라벨 = 충돌. 현재 진행 중인 쟁점을 강조하는 것이 이 시각화의 주 역할이다.

### 형태
행 = 이슈/쟁점, 열 = 리뷰어 6명인 격자(CSS grid). 두 블록으로 나뉜다.
- 블록 A "합의 — 상위 5개 이슈": 5행
- 블록 B "충돌 — 미해결 쟁점": 6행

두 블록 사이에 블록 제목(20px)과 헤어라인. 블록 B가 시각적으로 더 무겁다: 행 높이 72px(블록 A는 56px), 행 제목 20px 굵게.

### 치수
- 왼쪽 행 제목 열 320px: 블록 A는 "1위 — 3층 배치 미정의"처럼 순위 + 12자 안팎 짧은 제목, 블록 B는 "쟁점 1 — F1은 BLOCKING인가"처럼 번호 + 짧은 제목. 짧은 제목은 빌더가 SYNTHESIS 소제목에서 줄이되 의미를 바꾸지 않는다. 두 줄까지 허용.
- 리뷰어 열 6개 × 약 125px. 열 머리글은 짧은 이름(1.2절), 18px.
- 전체 폭 1100px 안에 맞는다.

### 셀 내용
**블록 A 셀**: 그 리뷰어가 이 이슈의 원본 지적자이면 지적 ID의 F번호(예: "F2 · F4")를 20px로 표시하고, 셀 아래쪽에 그 원본의 1라운드 심각도 색으로 2px 선을 긋는다(여러 개면 가장 높은 등급). 원본 지적자가 아니지만 2라운드에서 이 이슈를 언급했으면 "2라운드 언급" 16px 보조 텍스트. 둘 다 아니면 빈 셀(가운데 점 없이 완전히 빈 칸).
- 행 끝(격자 오른쪽 바깥이 아니라 행 제목 아래 줄)에 "지적 6명"처럼 원본 지적자 수.

**블록 B 셀**: 그 리뷰어의 입장 라벨(6자 이내 한국어, 16~18px, 주 텍스트 색) + 근거 항목 ID(14px 보조 텍스트, 예: "2R C1"). 입장이 없으면 빈 셀. 한 셀에 입장이 두 개면 두 줄로 쌓는다.
- 같은 행에서 입장 라벨이 다르다는 것 자체가 충돌을 보여 준다. 색으로 편을 가르지 않는다(색은 심각도 전용). 대신 행마다 입장 라벨 종류가 2개 이상이면 행 제목 오른쪽에 "입장 N개로 갈림" 보조 텍스트를 붙인다.

### 블록 B 검증용 참고치(SYNTHESIS 2장에서 추출)

| 쟁점 | 시스템 | 내러티브 | 심리 | 실현성 | QA | 비즈니스 |
|---|---|---|---|---|---|---|
| 1. systems-designer/F1 등급 | BLOCKING 유지 (C1) | — | 조건부 하향 (C1) | MAJOR 하향 (C1) | MAJOR 하향 (C1) | 기준 먼저 (L3) |

입장 라벨은 위 표현을 쓰거나, 빌더가 SYNTHESIS 원문에서 같은 의미로 6자 안팎으로 줄인다. 새 입장을 만들지 않는다. "—"는 빈 셀이다.

### 인터랙션
- **셀 호버/포커스**: 툴팁 — 첫 줄 리뷰어 전체 이름(18px), 둘째 줄 입장 라벨 또는 지적 ID, 셋째 줄부터 SYNTHESIS에 적힌 해당 리뷰어 논지 1~2문장(16px), 마지막 줄 근거 항목 ID 목록. 빈 셀은 툴팁 없음.
- **셀 클릭**: 블록 A 셀이면 해당 지적 ID로 V5 이동(1.4절 규칙). 블록 B 셀이면 그 행 아래에 상세 패널을 펼친다(아래).
- **블록 B 행 제목 클릭**: 행 바로 아래에 전체 폭 상세 패널을 펼친다. 패널 내용: 입장별로 묶은 2~3단 "입장 대 입장" 구성(1100px에서 입장 수만큼 열, 3개 초과면 2열로 줄바꿈). 각 열 머리 = 입장 라벨, 그 아래 리뷰어 칩과 논지 요약. 패널 맨 아래 "상위로 올릴 결정:" + SYNTHESIS 문장(20px, 주 텍스트 색). 한 번에 한 패널만 열린다. Esc로 닫는다.
- **블록 A 행 제목 클릭**: V1의 해당 카드로 스크롤하고 카드를 펼친다.
- **열 머리글 호버**: 해당 열 전체 셀 배경을 #2A2F38로 바꿔 한 리뷰어의 입장을 세로로 훑을 수 있게 한다. 행 제목 호버도 같은 방식으로 행을 강조한다.

### 범례(격자 위, 한 줄)
"블록 A: 칸의 숫자는 그 리뷰어의 원본 지적 ID, 아래 선 색은 1라운드 심각도(BLOCKING · 치명 / MAJOR · 주요 / MINOR · 경미)  ·  블록 B: 칸의 문구는 2라운드에서 밝힌 입장". 심각도 세 개는 실제 태그 모양으로 그린다.

### 빈 상태
미해결 쟁점이 0개면 블록 B 자리에: "보드가 합의에 도달했습니다 — 너무 쉬워 보인다면 2라운드를 다시 실행하세요."

## 5. V3 — 교차 검토 매트릭스

### 목적
2라운드에서 누가 누구의 지적과 논쟁했고(충돌), 누가 누구의 지적과 결합해 새 문제를 찾았는지(연결)를 보여 준다. "각자 따로 리뷰"가 아니라 "서로 읽고 반응했다"는 멀티 에이전트 과정의 증거다. 노드-링크 네트워크 대신 방향 매트릭스를 쓴다(0장 참조).

### 형태
6×6 방향 매트릭스(CSS grid). 행 = 검토한 리뷰어(2라운드 작성자), 열 = 검토받은 리뷰어(참조된 지적의 주인). 대각선(자기 자신)은 빗금 없이 #1F232B 빈 칸, 내용 없음.
- 행 제목 열 220px(전체 이름), 데이터 열 6개 × 140px, 셀 높이 84px.
- 행 합계 열("보낸 참조")과 열 합계 행("받은 참조")을 격자 바깥에 보조 텍스트로 둔다.
- 격자 제목 위 축 설명: 세로축 "검토한 리뷰어 →", 가로축 "← 검토받은 리뷰어의 지적". 한국어 라벨이 좁은 열에서 잘리지 않도록 가로축 설명은 격자 위 한 줄 텍스트로 둔다(회전 텍스트 금지).

### 셀 내용
두 줄 숫자:
```
충돌 3
연결 1
```
- "충돌 n"은 20px 주 텍스트 색, "연결 m"은 20px 보조 텍스트 색. 0이면 해당 줄에 "—".
- 셀 강도 표현: 충돌+연결 합계에 비례해 셀 배경을 #1F232B(0)에서 #3A404B(최대)까지 단계적으로 밝게 한다(무채색 5단계). 색상(hue)은 쓰지 않는다.
- 매트릭스 위에 표시 전환 버튼 3개(세그먼트): "전체" / "충돌만" / "연결만". "충돌만"이면 셀에 충돌 숫자만 크게(28px), 배경 강도도 충돌 수 기준. "연결만"도 같은 방식.

### 필요한 데이터(의미)
2라운드 교차 검토 항목 목록. 각 항목: 작성 리뷰어, 항목 종류(충돌 / 연결 / 수정), 항목 번호(C1, L3 등), 참조한 동료 지적 ID 목록, 요지 1~2문장.
- 셀 값 = 행 리뷰어가 쓴 충돌(또는 연결) 항목 중 열 리뷰어의 지적을 참조한 **항목 수**. 한 항목이 같은 동료의 지적 두 개를 참조해도 1로 센다. 한 항목이 동료 두 명을 참조하면 두 셀에 각각 1.
- "수정" 항목은 매트릭스 숫자에 넣지 않는다(자기 지적 조정이므로). 상세 패널에서도 제외.

### 검증용 참고치(설계자가 리뷰 파일에서 직접 센 값, 형식 "충돌/연결")
주 참조 대상 기준. 항목 안에서 근거로만 스치듯 언급된 동료(예: player-psychologist C1의 adversarial-qa/F3)는 세지 않았다. JSON 집계와 1~2 차이가 날 수 있다.

| 검토자 → | 시스템 | 내러티브 | 심리 | 실현성 | QA | 비즈니스 |
|---|---|---|---|---|---|---|
| 시스템 디자이너 | · | 0/2 | 2/1 | 0/2 | 1/2 | 2/0 |
| 내러티브 비평가 | 0/2 | · | 1/3 | 1/1 | 1/1 | 1/0 |
| 플레이어 심리 전문가 | 3/1 | 1/0 | · | 1/1 | 1/2 | 1/1 |
| 기술 실현성 리드 | 2/1 | 0/0 | 0/3 | · | 2/1 | 2/1 |
| 적대적 QA | 2/1 | 1/0 | 3/1 | 0/2 | · | 1/1 |
| 제작/비즈니스 분석가 | 1/3 | 1/2 | 1/2 | 2/2 | 1/3 | · |

관찰 포인트(빌더는 이 문장을 페이지에 넣지 않는다. 시각화가 이것을 드러내는지 확인하는 용도): 충돌을 가장 많이 받은 쪽은 시스템 디자이너(8건, 대부분 F1 등급 논쟁), 연결을 가장 많이 보낸 쪽은 제작/비즈니스 분석가다.

### 인터랙션
- **셀 호버/포커스**: 툴팁 "플레이어 심리 전문가 → 시스템 디자이너 · 충돌 3 · 연결 1" + 참조된 지적 ID 목록(예: "systems-designer/F1, F2, F3").
- **셀 클릭**: 매트릭스 바로 아래 상세 패널(전체 폭)에 해당 방향의 항목 목록을 표시한다. 두 단: 왼쪽 "충돌", 오른쪽 "연결". 각 항목: `player-psychologist · 2라운드 C1` · 참조 지적 ID(링크) · 요지 1~2문장(18px). 선택된 셀은 주 텍스트 색 2px 테두리.
- **역방향 보기 버튼**: 상세 패널 오른쪽 위 "반대 방향 보기(시스템 디자이너 → 플레이어 심리 전문가)". 누르면 대칭 셀을 선택한다. 논쟁이 쌍방향이었는지 확인하는 용도다.
- **행/열 제목 클릭**: 그 리뷰어의 보낸(행) 또는 받은(열) 항목 전체를 상세 패널에 리뷰어별로 묶어 표시한다.
- **빈 셀(0/0) 클릭**: 상세 패널에 "이 방향으로는 교차 참조가 없습니다." 표시.
- 기본 상태: 상세 패널은 "칸을 누르면 해당 리뷰어 사이의 교차 검토 항목을 볼 수 있습니다." 안내 문구만 보여 준다(자동 선택 없음).

### 빈 상태
2라운드 항목이 전혀 없으면 매트릭스 대신: "2라운드 교차 검토 기록이 없습니다. 2라운드를 먼저 실행하세요."

## 6. V4 — 심각도 분포 (라운드 전환 포함)

### 목적
지적이 BLOCKING · 치명, MAJOR · 주요, MINOR · 경미에 어떻게 분포하는지 리뷰어별·전체로 보여 주고, 2라운드 교차 검토가 등급을 얼마나 바꿨는지(4건)를 정직한 크기로 보여 준다. 지적 사항 흐름 시각화의 역할을 이 섹션이 대신한다.

### 형태
가로 누적 막대 7줄(리뷰어 6 + "전체"). 오른쪽에 등급 변경 목록.

레이아웃(1100px):
- 왼쪽 막대 영역 720px: 행 라벨 열 200px(전체 이름, 18px) + 막대 460px + 합계 숫자 60px.
- 오른쪽 변경 목록 340px, 사이 간격 40px.
- 막대 높이 36px, 행 간격 16px. "전체" 행은 헤어라인으로 위와 구분하고 막대 높이 44px, 라벨 굵게.
- 리뷰어 행 막대 길이는 개수 기준(1개 = 460/5 = 92px, 리뷰어당 최대 5). "전체" 행은 30개를 460px에 맞춘 **별도 척도**이며, 막대 아래에 "전체 행은 척도가 다릅니다(30개 기준)" 14px 보조 텍스트를 반드시 둔다.

### 막대 인코딩
- 구간 순서 왼쪽부터 BLOCKING → MAJOR → MINOR.
- 구간 채움: 심각도 색 단색(BLOCKING #E5484D, MAJOR #F5A623, MINOR #5A6270). 구간 사이 2px 배경색 간격.
- 각 구간 안에 개수를 18px로 표시(BLOCKING·MINOR 위 글자는 #E8E6E1, MAJOR 위 글자는 #16181D로 대비 확보). 구간 폭이 40px 미만이면 숫자를 생략하고 툴팁에만 둔다.

### 라운드 전환
막대 위 세그먼트 버튼 2개: "1라운드 등급" / "2라운드 최종 등급". 기본값 "2라운드 최종 등급".
- 전환은 즉시(애니메이션 없음).
- 전환 시 등급이 바뀐 지적이 있는 행은 행 라벨 옆에 "등급 변경 1" 같은 16px 보조 텍스트를 계속 표시한다(두 상태 모두).

### 검증용 참고치

| 리뷰어 | 1라운드 B/M/m | 2라운드 최종 B/M/m | 변경 |
|---|---|---|---|
| 시스템 디자이너 | 1/3/1 | 1/3/1 | 없음 |
| 내러티브 비평가 | 0/3/2 | 0/3/2 | 없음 |
| 플레이어 심리 전문가 | 0/5/0 | 0/4/1 | F5 하향 |
| 기술 실현성 리드 | 0/3/2 | 1/2/2 | F1 상향 |
| 적대적 QA | 0/4/1 | 0/4/1 | F1 하향, F5 상향(분포는 같지만 구성은 바뀜) |
| 제작/비즈니스 분석가 | 1/3/1 | 1/3/1 | 없음 |
| 전체 | 2/21/7 | 3/19/8 | 4건 |

적대적 QA처럼 분포 숫자는 같지만 내부 지적이 교차한 경우가 있다. 그래서 막대만으로는 변경이 보이지 않을 수 있고, 오른쪽 변경 목록이 필수다.

### 오른쪽 "2라운드 등급 변경 4건" 목록
제목 "2라운드 등급 변경" + 건수(28px). 항목마다 3줄:
1. 지적 ID(링크) · 리뷰어 칩
2. 이전 심각도 태그 → 이후 심각도 태그, 그 옆 "등급 상향" 또는 "등급 하향"(16px)
3. 이유 한 문장(16px 보조 텍스트, 리뷰 파일 "수정" 항목에서 줄임)

참고치:
- feasibility-lead/F1: MAJOR · 주요 → BLOCKING · 치명, 등급 상향 — 3층 미정의 참조를 네 명이 독립적으로 찾았고 문서가 3층을 구현할 수 없게 함.
- adversarial-qa/F5: MINOR · 경미 → MAJOR · 주요, 등급 상향 — seed가 유일한 재현·검증 수단인데 기본 실행 경로에서 작동하지 않음.
- adversarial-qa/F1: MAJOR · 주요 → MINOR · 경미, 등급 하향 — 적용될 상황이 없는 죽은 문장, 지우면 끝남.
- player-psychologist/F5: MAJOR · 주요 → MINOR · 경미, 등급 하향 — 주 사용자가 개발자·수강생일 가능성이 높아 재도전 동기는 핵심 요구가 아님.

목록 아래 14px 보조 텍스트: "나머지 26건은 2라운드에서 등급이 바뀌지 않았습니다. 철회된 지적은 없습니다." (숫자는 데이터에서 계산한다.)

### 인터랙션
- **막대 구간 호버/포커스**: 툴팁 "플레이어 심리 전문가 · MAJOR · 주요 · 4건" + 해당 지적 ID 목록.
- **막대 구간 클릭**: V5 필터를 "리뷰어 = 그 리뷰어, 심각도 = 그 등급, 기준 = 현재 전환 상태"로 설정하고 V5로 스크롤. "전체" 행 구간 클릭은 리뷰어 필터 없이 심각도만 설정.
- **행 라벨 클릭**: V5 필터를 그 리뷰어만으로 설정하고 스크롤.
- **변경 목록 항목 클릭**: V5의 해당 행으로 이동(1.4절).

### 빈 상태
지적이 0개면: "표시할 지적이 없습니다. 1라운드를 먼저 실행하세요."

## 7. V5 — 전체 지적 표 (필터·정렬)

### 목적
30개 지적 전부를 한곳에서 찾고 비교하는 드릴다운 영역. 다른 네 시각화의 클릭이 모두 여기로 모인다. 빽빽해도 된다.

### 형태
상단 필터 막대 + 행 목록(표 형태의 펼침 행). 박스 없이 행 사이 #2A2F38 헤어라인.

### 필터 막대
섹션 제목 바로 아래. V5 영역을 스크롤하는 동안 필터 막대는 `position: sticky; top: 0`으로 붙는다(배경 #16181D, 아래 헤어라인). 세 줄 구성:

1. **리뷰어**: 칩 버튼 7개 — "전체" + 전체 이름 6개. 다중 선택. 아무것도 선택하지 않으면 "전체"와 같다. 선택된 칩은 주 텍스트 색 테두리+글자, 선택 안 된 칩은 보조 색.
2. **심각도**: 태그 모양 토글 3개 — "BLOCKING · 치명", "MAJOR · 주요", "MINOR · 경미". 다중 선택. 선택되면 심각도 색 테두리, 해제되면 #2A2F38 테두리와 보조 색 글자. 각 태그 뒤에 현재 조건에서의 개수 "(3)".
   같은 줄 오른쪽에 **등급 기준** 세그먼트: "1라운드 등급" / "2라운드 최종 등급"(기본값). 심각도 필터와 행의 심각도 태그가 이 기준을 따른다.
3. **라운드 변화**: 세그먼트 "전체" / "2라운드에서 등급이 바뀐 지적만" / "2라운드에서 동료에게 언급된 지적만".
   같은 줄 오른쪽에 **정렬** 선택(`<select>`): "리뷰어·ID 순"(기본), "심각도 높은 순", "동료 언급 많은 순".
   맨 오른쪽 텍스트 버튼 "필터 초기화".

필터 막대 아래 한 줄 결과 요약(16px 보조): "30건 중 7건 표시 · 리뷰어: 적대적 QA · 심각도: MAJOR · 주요 (2라운드 최종 기준)".

### 행 구성(접힘)
한 행 높이 약 64px, 한 줄에:
- 심각도 태그(현재 기준 등급), 폭 150px 고정 열
- 지적 ID `adversarial-qa/F3` (16px 고정폭 느낌의 시스템 UI, 보조 색), 폭 220px
- 지적 제목(18px, 주 텍스트, 남은 폭, 두 줄까지)
- 오른쪽 끝: 등급이 바뀐 지적이면 "등급 상향"/"등급 하향" 16px 텍스트, 동료 언급 수 "언급 4"(16px 보조), 교차 검토 결과 태그(데이터에 값이 있을 때만)

행 전체가 펼침 버튼이다.

### 행 구성(펼침)
행 아래로 들여쓰기 150px(태그 열 폭)만큼 두고:
1. **문제** — 리뷰 파일 "문제" 단락의 요약(18px). 줄임만 허용, 바꿔 쓰기 금지.
2. **근거 구절** — 원문 인용을 그대로(따옴표 유지, 원래 언어 유지). 최대 4개, 더 있으면 "근거 N개 더 보기".
3. **등급 이력** — "1라운드 MAJOR · 주요 → 2라운드 BLOCKING · 치명" 태그 두 개와 리뷰어 본인의 2라운드 수정 이유 한 문장. 변경이 없으면 "2라운드에서 등급 유지" 한 줄.
4. **이 지적을 언급한 동료 항목** — `adversarial-qa · 2라운드 C1` + 입장 구분(충돌/연결) + 요지 한 문장. 없으면 "2라운드에서 이 지적을 직접 언급한 동료가 없습니다."
5. **상위 이슈 연결** — 이 지적이 V1 상위 5개 이슈의 원본이면 "상위 이슈 1위의 원본 지적" 링크 → V1 카드로 이동.

### 정렬 규칙
- "리뷰어·ID 순": 1.2절 리뷰어 순서, 그 안에서 F1→F5.
- "심각도 높은 순": 현재 기준 등급 BLOCKING → MAJOR → MINOR, 동률은 리뷰어·ID 순.
- "동료 언급 많은 순": 2라운드에서 이 지적을 참조한 동료 항목 수 내림차순, 동률은 심각도 → 리뷰어·ID. 이 수를 데이터에서 얻을 수 없으면 이 정렬 옵션과 "동료에게 언급된 지적만" 필터, 행의 "언급 N"을 모두 숨긴다(추정 금지).

### 인터랙션
- 필터·정렬 변경은 즉시 반영, 페이지 새로고침 없음. 펼쳐져 있던 행은 필터 후에도 보이면 펼친 상태 유지.
- 심각도 태그 개수 "(n)"는 리뷰어·라운드 변화 필터를 적용한 상태에서 각 등급의 개수.
- 외부(V1~V4)에서 필터를 설정하고 들어오면 필터 막대에 그 상태가 그대로 보이고, 결과 요약 줄 앞에 "다른 차트에서 설정된 필터" 16px 보조 텍스트를 2초가 아니라 **다음 필터 조작 전까지** 표시한다.
- 행 안의 지적 ID 링크는 1.4절 규칙을 따른다.

### 빈 상태
필터 결과 0건: 행 목록 자리에 "조건에 맞는 지적이 없습니다. 필터를 줄이거나 초기화하세요." + "필터 초기화" 버튼.

## 9. 충실도·접근성 점검 항목 (viz-reviewer용)

- 모든 표시 텍스트는 리뷰 파일 또는 SYNTHESIS로 추적 가능해야 한다. 요지는 줄일 수 있지만 완화·과장·재서술은 안 된다.
- 리뷰어 귀속과 지적 ID가 정확한지(특히 V2·V3의 방향과 V1 원본 목록).
- 헤더와 V4의 합계가 V5 전체 행 수와 일치하는지(30, 최종 BLOCKING 3).
- 심각도·결과 표시가 1.1절 문자열과 정확히 일치하는지, 필터·범례·툴팁까지 포함해서.
- 3위 이슈의 BLOCKING · 치명 + WEAKENED · 약화 조합에 단서 문구가 붙어 있는지.
- V4 "전체" 행의 척도 차이 안내가 있는지.
- 색이 심각도 외 용도로 쓰이지 않았는지(V2·V3는 무채색만).
- 키보드만으로 모든 펼침·필터·셀 선택이 가능한지, 툴팁이 포커스에서도 뜨는지.
- 1920×1080 프로젝터 해상도에서 지적 텍스트 18px 이상, 매트릭스 숫자 20px 이상인지. 1100px 폭에서 한국어 라벨이 잘리거나 한 글자씩 줄바꿈되지 않는지(`keep-all` 확인).
